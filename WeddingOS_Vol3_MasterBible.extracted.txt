1651: 16. WEBHOOK HANDLER COMPLETE GUIDE
1652: 16.1 Webhook Ingestion Architecture
1653: All webhooks go to a single endpoint: POST /webhooks/{source}
1654: Each webhook immediately stored to webhook_events table (raw body + headers)
1655: Acknowledgement returned to caller instantly (200 OK)
1656: Processing happens asynchronously via BullMQ — never block the webhook response
1657: Idempotency: Each webhook has a unique ID; check if already processed before acting
1658: 16.2 Webhook Events Table
1659: CREATE TABLE webhook_events (
1660: id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
1661: source VARCHAR(50) NOT NULL,     -- 'razorpay','freshdesk','msg91'
1662: event_type VARCHAR(100),         -- 'payment.captured'
1663: external_id VARCHAR(255),        -- Razorpay event ID for idempotency
1664: raw_headers JSONB,
1665: raw_body JSONB,
1666: processing_status ENUM('pending','processing','processed','failed'),
1667: processed_at TIMESTAMPTZ,
1668: error_message TEXT,
1669: retry_count INTEGER DEFAULT 0,
1670: created_at TIMESTAMPTZ DEFAULT NOW()
1671: );
1672: 16.3 Webhook Router
1673: // POST /webhooks/:source
1674: router.post('/:source', rawBody, async (req, res) => {
1675: const { source } = req.params;
1676: // 1. Immediately acknowledge
1677: res.status(200).json({ received: true });
1678: // 2. Verify signature synchronously (before enqueue)
1679: if (!verifySignature(source, req)) {
1680: logger.warn({ source }, 'Webhook signature verification failed');
1681: return; // Already sent 200 — discard
1682: }
1683: // 3. Store raw event
1684: const event = await webhookRepo.create({
1685: source, event_type: req.body.event,
1686: external_id: req.body.id,
1687: raw_headers: req.headers, raw_body: req.body
1688: });
1689: // 4. Enqueue for async processing
1690: await webhookQueue.add('process-webhook', { eventId: event.id }, {
1691: attempts: 3, backoff: { type: 'exponential', delay: 5000 }
1692: });
1693: });

2086: 21. VENDOR PAYOUT RECONCILIATION PROCESS
2087: Payout reconciliation ensures every rupee collected from customers is correctly distributed to vendors, platform, and tax authorities. This process runs daily. Any discrepancy triggers an alert.
2088: 21.1 Daily Reconciliation Flow
2089: Pull: All Razorpay payments captured yesterday from our DB
2090: Pull: Razorpay settlement report for same period via API
2091: Cross-check: Every payment_id in our DB must exist in Razorpay report
2092: Amount check: Our DB amount (in paise) must match Razorpay captured amount
2093: Fee check: Razorpay fee deducted must match expected (2% of amount)
2094: Escrow check: All captured payments must have a corresponding escrow_hold
2095: Discrepancy: Any mismatch → create reconciliation_discrepancy record → alert ops
2096: Report: Generate daily reconciliation report → send to finance email
